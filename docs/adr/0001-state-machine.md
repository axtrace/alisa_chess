# ADR-0001: Конечный автомат состояний навыка через SkillState

- **Статус:** Accepted
- **Дата:** 2025-11-01
- **Авторы:** alisa_chess team

## Контекст

Голосовой навык — диалоговый сценарий с большим количеством веток (выбор цвета, ожидание хода, подтверждение ничьей/сдачи/новой игры, ввод уровня сложности, завершение партии). Платформа Алисы не хранит явного состояния разговора — состояние пробрасывается между запросами через `state.user.game_state` и `session_state`.

Альтернативы, которые рассматривались:

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Один большой `if/elif` в `handler`** | Минимум абстракций | Растущая когнитивная сложность, нельзя изолированно тестировать ветки, легко забыть про edge case |
| **B. Внешний state-machine фреймворк (`transitions`, `xstate`-подобные)** | Декларативность, визуализация | Дополнительная зависимость, cold start, проблемы с миграцией состояния, оверкилл для ~10 узлов |
| **C. Перечисление + per-state handler класс** | Каждый узел изолирован, легко тестировать, добавление состояния — добавление файла, явный enum | Нужна дисциплина импортов и регистрации |

## Решение

Принят вариант **C**. Состояния перечислены в [`SkillState(str, Enum)`](../../skill_state.py), а на каждое состояние выделен отдельный обработчик в [`handlers/`](../../handlers/), наследующийся от [`BaseHandler`](../../handlers/base_handler.py).

Ключевые правила:

1. **Тип состояния — enum.** Сравнения внутри кода — только с `SkillState.X`, не со строками. Наследование от `str` сохраняет обратную совместимость со старым state в продакшене (V1 хранил состояние как строку).
2. **Один файл — одно состояние.** Имя файла отражает состояние (`waiting_move_handler.py` → `SkillState.WAITING_MOVE`).
3. **Маршрутизация — в [`AliceChess.handle_request`](../../alice_chess.py).** Выбор хендлера по `game.skill_state`. Переход в новое состояние — присваивание `game.set_skill_state(SkillState.X)`, при этом запоминается `prev_skill_state` для отката.
4. **Спец-интенты — отдельный «горизонтальный» хендлер** [`SpecialIntentHandler`](../../handlers/special_intent_handler.py). Help/undo/repeat/show_board/set_skill_level работают из почти любого состояния через реестр `_intent_registry: list[tuple[validator_name, handler_method]]`.
5. **Per-handler exception safety.** [`BaseHandler.safe_handle`](../../handlers/base_handler.py) оборачивает `handle()` в try/except, чтобы исключение в одном состоянии не сваливало всю функцию.

## Последствия

**Плюсы:**
- Добавление состояния — изолированное локальное изменение (новый файл + строка enum + ветка в маршрутизаторе).
- Хендлеры юнит-тестируются независимо, без подъёма всего `AliceChess`.
- Явный enum гарантирует typo-safety (mypy ловит `SkillState.WAINTING_MOVE`).

**Минусы и компромиссы:**
- Маршрутизация всё ещё императивна (цепочка проверок в `handle_request`), а не таблица «состояние × событие → следующее состояние». Это сознательное упрощение: переходы зависят от валидаторов и содержимого `request`, а не только от `(state, event)`-пары.
- Запись `SkillState(str, Enum)` означает, что `state == 'WAITING_MOVE'` тоже работает — мы намеренно сохранили совместимость со старыми сериализованными состояниями (см. [ADR-0003](0003-game-state-serialization.md)).
