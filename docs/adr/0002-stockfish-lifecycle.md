# ADR-0002: Жизненный цикл Stockfish в serverless

- **Статус:** Accepted
- **Дата:** 2025-11-01
- **Авторы:** alisa_chess team

## Контекст

[Stockfish](https://stockfishchess.org/) — внешний бинарный процесс, общающийся с Python через UCI. [python-chess](https://github.com/niklasf/python-chess) поднимает его как subprocess через `chess.engine.SimpleEngine.popen_uci(...)`.

В Yandex Cloud Functions есть две особенности, критически меняющие модель работы движка:

1. **Cold start.** На первый вызов после простоя контейнер инициализируется с нуля. Запуск Stockfish добавляет ~50–150 ms.
2. **Warm container.** Один и тот же контейнер обслуживает несколько запросов подряд. Внутри одного запроса допустимо открыть subprocess, но между запросами объекты Python не пересоздаются автоматически — оставленный «висеть» движок утечёт.

Без явного управления возможны два класса багов:

- **Утечка процесса.** Если объект `Game` собран GC, но `SimpleEngine` не закрыт явно — subprocess живёт до конца жизни контейнера, потребляя память и хендлы.
- **Холодный старт даже на «дешёвых» запросах.** Если поднимать движок в `Game.__init__`, любой запрос (даже help/repeat) будет ждать Stockfish.

История проблемы: раньше очистка делалась через `Game.__del__`, что в serverless нестабильно (порядок финализации не гарантирован, исключения подавляются).

## Решение

1. **Ленивая инициализация.** Поле `Game._engine` начинается с `None`. Реальный `popen_uci(...)` происходит при первом обращении к property `Game.engine` (используется только в `comp_move` и в `set_skill_level`, если движок уже поднят).
2. **Контекстный менеджер.** [`Game.__enter__/__exit__`](../../game.py) гарантирует `engine.quit()` на выходе. `AliceChess.__enter__/__exit__` пробрасывает это наружу.
3. **`with`-блок в serverless.** [`alice_serverless.handler`](../../alice_serverless.py) пишет `with AliceChess() as alice: …`. На любом исключении внутри блока `__exit__` корректно закроет subprocess.
4. **Безопасный `quit()`.** Метод [`Game.quit`](../../game.py) идемпотентен и не падает повторно: `if self._engine is not None: try: self._engine.quit() except …`.
5. **Тесты не запускают реальный бинарь.** Глобальная autouse-фикстура в [`tests/conftest.py`](../../tests/conftest.py) подменяет `chess.engine.SimpleEngine.popen_uci` фейком, даже если конкретный тест забыл декоратор `@patch`.

## Последствия

**Плюсы:**
- Дешёвые сценарии (help, show_board, undo, repeat) не платят за cold start Stockfish.
- Нет утечек subprocess'ов между запросами.
- `__del__` больше не используется — финализация детерминирована.
- Тесты быстрые и не зависят от наличия бинаря на машине разработчика.

**Минусы и компромиссы:**
- В warm container движок поднимается заново на каждый запрос с реальным ходом. Это сознательный trade-off: между запросами могут смениться `skill_level` / `time_level`, и переиспользование одного процесса усложнило бы инвариант «изолированный запрос». Если профилирование покажет, что инициализация дорогая, можно ввести кэш на уровне модуля с явным TTL.
- `Game` обязательно использовать как контекстный менеджер. Прямой вызов `Game()` без `with` оставит utility `quit()` обязанностью вызывающего.

## Инварианты, которые нельзя нарушать

- `engine.quit()` гарантирован для любого пути выхода (success / exception / handler-level safe_handle).
- Stockfish-бинарь НЕ коммитится в репозиторий и кладётся рядом как `./stockfish` при деплое.
- В юнит-тестах ни один путь не должен дотянуться до реального `popen_uci` — autouse-фикстура должна оставаться в `tests/conftest.py`.
